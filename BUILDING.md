# Building & Flashing lilbud

Three build targets:

| Target | Feature flag | Use |
|--------|-------------|-----|
| **Desktop** (SDL2) | `desktop` | Preview — native SDL2 window |
| **WASM** (browser) | `wasm` | Preview — runs in any browser via Canvas 2D |
| **Embedded** (RP2040) | `embedded` | Production — Waveshare RP2040-LCD-1.28 pin |

The default Cargo target is `thumbv6m-none-eabi` (embedded). Desktop and WASM builds require passing the target explicitly.

---

## Prerequisites

### Rust toolchain

```sh
rustup target add thumbv6m-none-eabi
```

### elf2uf2-rs (UF2 conversion)

Converts the compiled ELF to a UF2 file the RP2040 bootloader accepts:

```sh
cargo install elf2uf2-rs
```

### SDL2 (desktop only)

```sh
# macOS
brew install sdl2

# Ubuntu / Debian
sudo apt-get install libsdl2-dev
```

### wasm-bindgen CLI (WASM only)

The `wasm-bindgen` CLI generates the JS glue that lets the browser load the `.wasm` file. Its version must match the `wasm-bindgen` crate version pinned in `Cargo.toml`:

```sh
cargo install wasm-bindgen-cli --version "=0.2.92" --locked
```

### probe-rs (optional — SWD flashing)

Only needed if you want to flash over SWD instead of UF2, or stream RTT debug output:

```sh
cargo install probe-rs-tools --locked
```

## Face Data Codegen

Face data is generated by [lil bud maker](https://github.com/zapplebee/lilbudmaker) and exported as NDJSON. Before building the embedded target, this data must be compiled into a static Rust file — no runtime JSON parsing happens on the device.

**Run this whenever you have new face data:**

```sh
python3 gen_faces.py /path/to/lilbudmaker/lilbudz.ndjson > src/face_data.rs
```

`gen_faces.py` reads each line of the NDJSON, extracts the 18 face points (`a`–`r`), applies the coordinate transform (`x // 2 + 50`, `y // 2 + 50`), and emits a `pub static FACE_DATA: &[[(i32, i32); 18]]` into `src/face_data.rs`.

A bundled `faces.ndjson` is included in the repo as a fallback. The desktop target reads face data at runtime via `FACE_FILE_PATH` instead.

---

## Desktop Build

```sh
# macOS Apple Silicon
FACE_FILE_PATH=/path/to/lilbudmaker/lilbudz.ndjson \
  cargo run --target aarch64-apple-darwin \
  --no-default-features --features desktop

# macOS Intel
FACE_FILE_PATH=/path/to/lilbudmaker/lilbudz.ndjson \
  cargo run --target x86_64-apple-darwin \
  --no-default-features --features desktop

# Linux x86_64
FACE_FILE_PATH=/path/to/lilbudmaker/lilbudz.ndjson \
  cargo run --target x86_64-unknown-linux-gnu \
  --no-default-features --features desktop
```

The `FACE_FILE_PATH` env var is read at compile time via `include_str!(env!("FACE_FILE_PATH"))` — it must be set for the build to succeed. It can point to either `faces.ndjson` (bundled) or a live `lilbudz.ndjson` from lilbudmaker.

## WASM Build

The WASM target renders into a `<canvas id="canvas">` element using the Canvas 2D API, driven by `requestAnimationFrame`. Face data is embedded at compile time via `FACE_FILE_PATH` (same as desktop).

### Prerequisites

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version "=0.2.92" --locked
```

### 1. Build the WASM binary

```sh
FACE_FILE_PATH=/path/to/lilbudmaker/lilbudz.ndjson \
  cargo build --release --target wasm32-unknown-unknown \
  --no-default-features --features wasm
```

Or with the bundled faces:

```sh
FACE_FILE_PATH=$(pwd)/faces.ndjson \
  cargo build --release --target wasm32-unknown-unknown \
  --no-default-features --features wasm
```

### 2. Generate JS bindings

```sh
wasm-bindgen target/wasm32-unknown-unknown/release/lilbud.wasm \
  --out-dir pkg --target web
```

This produces `pkg/lilbud.js` and `pkg/lilbud_bg.wasm`.

### 3. Serve locally

The browser requires a server (not `file://`) to load ES modules and `.wasm`:

```sh
# Python (no install needed)
python3 -m http.server 8080

# Then open: http://localhost:8080
```

The `index.html` at the repo root imports `./pkg/lilbud.js` and renders lilbud in a round `<canvas>` centered on the page.

## Embedded Build

`thumbv6m-none-eabi` is the default target in `.cargo/config.toml`, so no `--target` flag is needed.

### 1. Regenerate face data (if needed)

```sh
python3 gen_faces.py /path/to/lilbudmaker/lilbudz.ndjson > src/face_data.rs
```

### 2. Build release binary

```sh
cargo build --release --no-default-features --features embedded
```

Output ELF:

```
target/thumbv6m-none-eabi/release/lilbud
```

### 3. Convert to UF2

```sh
elf2uf2-rs target/thumbv6m-none-eabi/release/lilbud target/lilbud.uf2
```

## Flashing

### Method 1: UF2 Bootloader (no extra hardware)

1. **Hold the BOOT button** on the board
2. **Press RESET** (or plug in USB while holding BOOT)
3. The board mounts as **`RPI-RP2`** USB mass storage
4. Copy the UF2:

```sh
# macOS
cp target/lilbud.uf2 /Volumes/RPI-RP2/

# Linux (path may vary — check `lsblk` after connecting)
cp target/lilbud.uf2 /media/$USER/RPI-RP2/
```

The board reboots automatically and starts running lilbud.

### Method 2: probe-rs over SWD

Requires a debug probe (a second Pico running [picoprobe](https://github.com/raspberrypi/picoprobe), or a CMSIS-DAP adapter) connected to the board's SWD pins.

```sh
probe-rs download --chip RP2040 --format elf \
  target/thumbv6m-none-eabi/release/lilbud
```

Or configure `probe-rs` as the Cargo runner in `.cargo/config.toml` and use `cargo run --release`.

---

## Debug Output

The board has no serial output by default. With a probe-rs runner, RTT output streams to your terminal:

```sh
probe-rs run --chip RP2040 target/thumbv6m-none-eabi/release/lilbud
```

Without a probe, the display itself is the debug output: because `panic-halt` freezes the CPU without clearing GRAM, whatever was last written to the framebuffer stays visible on screen. A solid color fill just before a suspected panic site is a reliable crash indicator.

## .cargo/config.toml

```toml
[build]
target = "thumbv6m-none-eabi"

[target.thumbv6m-none-eabi]
rustflags = [
    "-C", "link-arg=--nmagic",
    "-C", "link-arg=-Tlink.x",
]
runner = "elf2uf2-rs"
```

The `runner` setting means `cargo run --release` (for the embedded target) will automatically convert the ELF and write it to the UF2 file. It does **not** auto-copy to the device — do that manually with `cp`.
