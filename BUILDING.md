# Building & Flashing lilbud

Three build targets:

| Target | What it is |
|--------|-----------|
| **Embedded** | RP2040 firmware — runs on the physical pin |
| **WebView host** | Rust native app — bridges the board to the dock UI |
| **Dock UI** | TypeScript web app — the companion interface |

The default Cargo target is `thumbv6m-none-eabi` (embedded). The WebView host requires passing the host triple explicitly.

---

## Prerequisites

### Rust toolchain

```sh
rustup target add thumbv6m-none-eabi
```

### elf2uf2-rs (UF2 conversion)

```sh
cargo install elf2uf2-rs
```

### Bun (dock UI)

```sh
curl -fsSL https://bun.sh/install | bash
```

Install dock UI dependencies once after cloning:

```sh
cd dock-ui && bun install
```

### probe-rs (optional — SWD flashing)

```sh
cargo install probe-rs-tools --locked
```

## Face Data Codegen

Face data is generated by [lil bud maker](https://github.com/zapplebee/lilbudmaker) and exported as NDJSON. Before building the embedded target, this data must be compiled into a static Rust file — no runtime parsing happens on the device.

```sh
make faces FACE_FILE=/path/to/lilbudmaker/lilbudz.ndjson
```

A bundled `faces.ndjson` is included in the repo as a fallback.

---

## WebView Host

The WebView host is a Rust native app (`wry`) that opens a window, connects to the board over USB, and loads the dock UI. It bridges face animation frames and filesystem commands between the board and the web UI.

### Dev

```sh
make webview
```

### macOS app bundle

```sh
make app     # → lilbud.app
make dist    # → lilbud-mac.zip
```

The app is unsigned. First-time openers on macOS must right-click → Open, or:

```sh
xattr -d com.apple.quarantine lilbud.app
```

---

## Dock UI

The dock UI is a TypeScript single-page app bundled and served by Bun.

### Dev mode (no board needed)

```sh
make dock-mock
```

Starts at `http://localhost:3000` with auto-cycling face animations and in-memory fixture data. The full UI — status editing, collected statuses, dismiss — is exercisable without hardware.

### Real mode (board connected)

```sh
make dock
```

Expects the WebView host to be running and forwarding board data.

### Override port

```sh
make dock-mock DOCK_PORT=4000
```

### Tests

```sh
cd dock-ui && bun test
```

## Embedded Build

`thumbv6m-none-eabi` is the default target in `.cargo/config.toml`.

### 1. Regenerate face data (if needed)

```sh
make faces FACE_FILE=/path/to/lilbudmaker/lilbudz.ndjson
```

### 2. Build

```sh
make embedded
```

Output ELF: `target/thumbv6m-none-eabi/release/lilbud`

### 3. Convert to UF2

```sh
make uf2
```

---

## Flashing

### Method 1: UF2 Bootloader (no extra hardware)

```sh
make flash
```

Or manually:

1. Hold BOOT on the board, press RESET (or plug in USB while holding BOOT)
2. The board mounts as `RPI-RP2`
3. Copy the UF2:

```sh
cp target/lilbud.uf2 /Volumes/RPI-RP2/     # macOS
cp target/lilbud.uf2 /media/$USER/RPI-RP2/ # Linux
```

Override mount point:

```sh
make flash MOUNT=/media/myuser/RPI-RP2
```

### Method 2: probe-rs over SWD

```sh
probe-rs download --chip RP2040 --format elf \
  target/thumbv6m-none-eabi/release/lilbud
```

---

## Debug Output

Without a probe, the display is the debug output: `panic-halt` freezes the CPU without clearing GRAM, so whatever was last written to the framebuffer stays visible.

With probe-rs:

```sh
probe-rs run --chip RP2040 target/thumbv6m-none-eabi/release/lilbud
```

## .cargo/config.toml

```toml
[build]
target = "thumbv6m-none-eabi"

[target.thumbv6m-none-eabi]
rustflags = [
    "-C", "link-arg=--nmagic",
    "-C", "link-arg=-Tlink.x",
]
runner = "elf2uf2-rs"
```
