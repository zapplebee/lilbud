# lilbud

Lil Bud is a tamagotchi-inspired character for embedded systems, written in Rust. He's a little animated face that smoothly morphs between expressions drawn from [lil bud maker](https://github.com/zapplebee/lilbudmaker).

The eventual goal is to build him onto a [Waveshare RP2040-LCD-1.28](https://www.waveshare.com/rp2040-lcd-1.28.htm) and wear him like a pin. For now, the only build target is SDL2 for desktop previewing.

## How It Works

### Face Data

Faces are generated by [lil bud maker](https://github.com/zapplebee/lilbudmaker) and stored as newline-delimited JSON (JSONL). Each line is a log entry with this shape:

```json
{"level":"info","message":{"emo":"happy","points":{"a":{"x":100,"y":80},...}}}
```

Points are labeled `a` through `r` and map to specific facial features:

| Points | Feature |
|--------|---------|
| `a`, `b`, `c`, `d` | Head outline (two triangles: `a-b-c` and `c-d-a`) |
| `e`–`p` (pairs) | Face line segments (`e-f`, `g-h`, `i-j`, `k-l`, `m-n`, `o-p`) |
| `q`, `r` | Eyes (filled circles) |

During deserialization, coordinates are scaled down (`x/2 + 50`, `y/2 + 50`) to keep the face centered and within the 240×240 canvas.

### Rendering

Each frame, `draw_ui()` renders into a `[Rgb565; 57600]` pixel buffer (240×240):

1. **Background**: filled blue
2. **Shadow layer**: the head quad (two triangles) drawn in purple with a small random offset, giving a jittery shadow effect
3. **Head**: the same quad drawn in green on top
4. **Face features**: six line segments in black (drawn with stroke width 2)
5. **Eyes**: two filled black circles

A small random jitter (1–5px) is applied to all face points each frame, giving Lil Bud a slightly wobbly, alive feeling.

### Animation

Lil Bud smoothly interpolates between faces. Two global states are maintained:

- **`FACE`** — the currently displayed face
- **`TARGET_FACE`** — the face being morphed toward

Each call to `tick()` moves every point in `FACE` 2px closer to the corresponding point in `TARGET_FACE`. Pressing the Right arrow key sets a new random target face.

### Main Loop

The main loop runs at ~60fps (16ms sleep per frame):

1. Poll SDL2 events
2. Call `tick()` to advance interpolation
3. Call `draw_ui()` to render into the pixel buffer
4. Flush the buffer to the SDL2 window via `SDL2Display::flush()`

## Project Structure

```
src/
├── main.rs          # SDL2 event loop and entry point
├── config.rs        # Display dimensions (WIDTH=240, HEIGHT=240)
├── get_faces.rs     # Load and deserialize face data from JSONL file
├── ui.rs            # Face state, interpolation, and rendering logic
└── sdl2_display.rs  # SDL2 canvas wrapper (Rgb565 buffer → screen)
```

## Setup

See **[BUILDING.md](BUILDING.md)** for full build and flash instructions covering both the SDL2 desktop target and the RP2040 embedded target.

Quick start for desktop preview:

```sh
brew install sdl2                           # macOS; see BUILDING.md for Linux
export FACE_FILE_PATH=/path/to/lilbudmaker/lilbudz.ndjson
cargo run
```

## Controls

| Key | Action |
|-----|--------|
| Right arrow | Pick a new random target face and begin morphing |
| Escape | Quit |

---

## Dependencies

| Crate | Purpose |
|-------|---------|
| [`sdl2`](https://crates.io/crates/sdl2) | Desktop window and event handling |
| [`embedded-graphics`](https://crates.io/crates/embedded-graphics) | Drawing primitives (circles, triangles, polylines) |
| [`serde` / `serde_json`](https://crates.io/crates/serde) | Deserializing face data from JSONL |
| [`rand`](https://crates.io/crates/rand) | Random face selection and per-frame jitter |
| [`heapless`](https://crates.io/crates/heapless) | No-std compatible data structures (for future embedded target) |
